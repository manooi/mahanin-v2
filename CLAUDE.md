## Commands

```bash
npm run dev       # Astro dev server (localhost:4321)
npm run build     # Build static site to dist/
npm run preview   # Serve the built dist/ locally
```

There are no test or lint commands — this is a static site. Verify by building and reading
`dist/index.html`.

## Architecture

Personal site at [mahanin.com](https://mahanin.com), built with Astro (static output). Two pages:

- **`src/pages/index.astro`** — the hub, a retro desktop styled as "Mahanin OS 94": boot
  screen, draggable windows, icon grid, taskbar with start menu, right-click menus, desktop
  widgets. Behaviour in `src/scripts/os94.js`, config in `src/data/os94.js`, components in
  `src/components/os94/`. **→ [`docs/features/os94-hub.md`](./docs/features/os94-hub.md)**
- **`src/pages/resume/index.astro`** — the resume, printable to PDF via the "Save as PDF" button
- `src/layouts/Base.astro` — shared head/meta shell; pages pass title/description/canonical/og
  props, and a named `head` slot lets pages inject extras (the hub uses it for font preloads)
- `public/fonts/` — self-hosted latin-subset woff2 (Silkscreen 400, IBM Plex Mono 400/600);
  no Google Fonts requests

## Key design decisions

- **Performance.** The resume keeps the original regime: ~20KB HTML+CSS and only a small
  `<script is:inline>` (age counter, IT-years counter, print-title swap), so Astro never
  bundles or defers it. The hub is heavier by design (~46KB HTML+inlined CSS, ~7.5KB bundled
  JS, 24KB fonts — ~13KB gz for the HTML) but still framework-free. Its JS ships as an
  Astro-bundled module rather than `is:inline` because the initial HTML is fully correct
  without JS, so deferral causes no flash and the asset caches separately.
- **All CSS is inlined into the HTML** (`build.inlineStylesheets: 'always'` in
  `astro.config.mjs`) — no render-blocking stylesheet requests.
- **Tailwind v3 wired manually** via `postcss.config.cjs` + `src/styles/global.css` (no
  `@astrojs/tailwind` — it peer-caps at Astro 5); utilities are purged against
  `src/**/*.astro`. The resume uses Tailwind utilities; the hub's OS94 CSS is bespoke and
  uses none.
- **The resume's `@media print` block powers PDF export** (page margins, 12px root font
  scaling, `.no-print`, page-break rules). Do not scope or restructure it.
- **Static files** (images as WebP, favicon, robots.txt, fonts) live in `public/`.
  `assets/profile.webp` serves `og:image`. Image details in the hub doc.
- **Sitemap** is generated by `@astrojs/sitemap` (`sitemap-index.xml`, referenced from
  `public/robots.txt`).

## Invariants

Short list; the why for each lives in
[`docs/features/os94-hub.md`](./docs/features/os94-hub.md#invariants--the-expensive-ones).

1. All OS94 CSS lives in the page's `<style is:global>` block — scoped styles miss JS-created DOM.
2. The initial HTML must be valid without JS. No window ships `is-open`; `init()` never touches open/min state.
3. The `<noscript>` link list must survive edits — it lives in `.desktop-readme`, not in a window.
4. Geometry lives exactly once, at the call site, as CSS custom properties. `DEFS` x/y is the pre-JS value only; `placeWin()` centres windows on first open.
5. `APPS` is the single source for the icon grid and start menu. `START_ORDER` mirrors it by id and must be edited alongside.
6. Parked windows must have zero openers left — but `taskman` and `netmon` are *not* parked; each has one bespoke opener.
7. Mobile reflows the desktop; it never gets a second copy of the markup.
8. `.widgets` is a `pointer-events: none` overlay — anything added inside needs the `auto` opt-in, except `.ghost-icon`.
9. Keep multi-line inline elements on one line in `.astro` markup — Astro collapses whitespace.
